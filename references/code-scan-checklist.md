# Code Scan Checklist · 结合历史代码要看什么

阶段 4 的检查清单。目标不是"把仓库读完"，而是**用需求关键词定位到相关实现，
拿到事实、差距和影响面**。所有结论按 `事实 / 推断 / 待确认` 标注，事实必须带 `path:line`。

## 0. 先跑盘点脚本

```bash
python3 scripts/scan_codebase.py --root <repo> --out 04-code-baseline.raw.md
python3 scripts/scan_codebase.py --root <repo> --focus "关键词1,关键词2" --format md
```

盘点给出：语言规模、项目清单、目录结构、入口点、路由、数据模型/迁移、测试、文档、TODO。
它是地图，不是结论；结论要靠下面定向阅读。

## 1. 仓库定位

- [ ] 项目清单：`package.json`、`pnpm-workspace.yaml`、`pnpm-lock`、`pyproject.toml`、`go.mod`、
      `Cargo.toml`、`pom.xml`、`build.gradle`、`requirements.txt`、`composer.json`。
- [ ] 是否 monorepo：workspace 包列表、包边界、共享库、依赖方向。
- [ ] 本次需求落在哪个包 / 服务 / 模块（写清楚，防止扫错范围）。
- [ ] 构建与运行方式：脚本、Dockerfile、部署清单。
- [ ] 版本与分支：当前分支、最近提交、release 标签。

## 2. 功能追踪链（最重要）

用需求里的名词/动词做全仓检索，沿链路追到底：

```text
路由/入口 → Controller/Handler → Service/Domain → Repository/DAO → Model/Schema → DB 表
                                     ↘ 事件/任务/外部调用
```

检索示例（`rg`，没有就用 grep）：

```bash
rg -n "退款|refund" --type ts --type py --type java --type go
rg -n "order.*status|订单状态" -g '!node_modules' -g '!dist'
rg -n "@(Get|Post|Put|Delete)Mapping|router\.(get|post)|app\.(get|post)" 
rg -n "class .*Service|def .*_service|func .*Service"
```

- [ ] 现有功能入口在哪（页面/路由/CLI/任务）。
- [ ] 关键业务逻辑在哪个 service/domain 文件。
- [ ] 数据读写走哪个 repository / ORM。
- [ ] 涉及哪些表、字段、枚举。
- [ ] 有无现成的相似功能可复用（同构能力）。

## 3. 数据层

- [ ] ORM 模型 / schema：`models/`、`schema.prisma`、`*.entity.ts`、`models.py`。
- [ ] 迁移：`migrations/`、`alembic/`、`db/migrate/`、`*.sql`；最近迁移时间。
- [ ] 表结构、主键、索引、唯一约束、外键、软删除字段。
- [ ] 枚举/状态字段的取值与含义（从代码或注释确认）。
- [ ] 数据量级线索：分区、分表、归档、批处理。
- [ ] 兼容性：新增字段是否可空、是否有默认值、是否需要回填。

## 4. 接口层

- [ ] 路由清单与版本策略（`/v1/`、`/api/`）。
- [ ] 请求/响应 DTO、校验规则、必填项。
- [ ] 错误码与错误结构（统一错误处理中间件）。
- [ ] 鉴权：token/session、网关、中间件。
- [ ] 幂等：幂等键、去重表、重试策略。
- [ ] 限流、超时、重试、熔断。
- [ ] 对外契约：OpenAPI/Swagger、SDK、文档。

## 5. 状态与流程

- [ ] 状态枚举、状态机代码、状态流转校验。
- [ ] 事件发布/订阅、消息队列 topic、消费者。
- [ ] 定时任务/调度（cron、quartz、Celery、crontab）。
- [ ] 补偿与对账任务。
- [ ] 并发控制：锁、乐观锁、版本号、分布式锁。

## 6. 权限与安全

- [ ] 角色/权限模型（RBAC/ABAC）、菜单/按钮权限。
- [ ] 鉴权中间件、越权校验点。
- [ ] 数据范围（租户、门店、组织）过滤。
- [ ] 审计日志、敏感字段脱敏。
- [ ] 本次需求是否引入新权限点 / 新角色。

## 7. 配置与开关

- [ ] 配置文件：`*.yaml/*.yml/*.json/*.env*`（**只读结构，不读密钥值**）。
- [ ] 环境变量清单（名称与用途，不记录值）。
- [ ] Feature flag / 灰度开关 / 动态配置。
- [ ] 本次需求是否需要新增开关。

## 8. 任务与消息

- [ ] 异步任务、队列、延迟队列。
- [ ] 消息 schema 与兼容策略。
- [ ] 重试、死信、补偿。

## 9. 外部集成

- [ ] 第三方 API 客户端（支付、短信、物流、风控、财务）。
- [ ] webhook 回调、回调验签、重放保护。
- [ ] 数据同步与一致性策略。

## 10. 观测

- [ ] 日志、指标、Trace 接入方式。
- [ ] 现有看板、告警规则。
- [ ] 本次需求要加哪些埋点/告警。

## 11. 测试

- [ ] 测试目录与框架（jest/vitest/pytest/go test）。
- [ ] 现有覆盖相关功能的测试（可作为行为事实来源）。
- [ ] 测试夹具、mock 数据、测试环境。
- [ ] 本次需求需要补哪些测试。

## 12. 历史与文档

- [ ] `git log --follow -p -- <file>` 看关键文件的演进。
- [ ] 查找废弃实现：`deprecated`、`legacy`、`TODO`、`FIXME`、`HACK`。
- [ ] ADR / 设计文档 / 历史 PRD / 需求单。
- [ ] 文档与实际代码是否一致（不一致记为待确认）。

## 13. 风险启发式（重点看）

- 高爆炸半径：被多处引用的核心模型/工具、公共库、鉴权中间件、支付/账务逻辑。
- 生成代码 / 自动生成文件：`*_pb2.py`、`*.g.dart`、`generated/`，改法不同。
- 遗留路径：注释掉的旧逻辑、双写、开关分支。
- 隐式契约：序列化格式、缓存 key、消息字段、DB 枚举。
- 时间/时区/金额精度/幂等：金融相关必查。

## 15. 没代码怎么办

- 明确写 `代码可用性 = 否`。
- `04-code-baseline.md` 只保留"需要 PM/研发提供的信息清单"：
  系统边界、涉及模块、数据表、接口、状态、权限、上下游、历史包袱。
- 后续方案与设计全部标"待代码验证"，不得假装有依据。
